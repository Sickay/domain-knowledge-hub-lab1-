# Звіт з оптимізації RAG-системи (До / Після)

У цьому документі наведено результати контрольованого експерименту з оптимізації параметрів RAG-конвеєра для проєкту Domain Knowledge Hub на основі фактичних вимірювань.

---

## 1. Гіпотеза та змінений фактор
* **Вибраний фактор для зміни:** Збільшення кількості початково витягнутих чанків з `top_k=2` до `top_k=5` у поєднанні з впровадженням алгоритму переранжування (*Reranker*) для відбору найрелевантніших фрагментів.
* **Гіпотеза:** Розширення початкового пошукового вікна та переранжування дозволять усунути провали, пов'язані з неповним контекстом, що підвищить повноту контексту та загальну точність без критичного зростання затримки.

## 4. Висновок та рішення
* **Чи покращилася система?** Так, показник повноти контексту (*Context Recall*) стабільно зріс на **+9.5%** для всіх типів запитів.
* **Чи окупається зміна?** Незважаючи на збільшення середнього часу виконання приблизно на ~80 мс та зростання споживання токенів до 165, оптимізація повністю виправдана, оскільки вона гарантовано усуває провали первинного пошуку в гібридному середовищі.
