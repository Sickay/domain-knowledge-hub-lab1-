# Проєкт зіркової схеми та бізнес-вимоги

## 1. Бізнес-процес і зерно факту
* **Бізнес-процес:** Реєстрація телеметричних подій, робочих циклів та показників датчиків виробничого обладнання (`PLC-01`, `CNC-01`, `SP-01`, `TS-01`).
* **Зерно факту (Grain):** Одна подія роботи обладнання за конкретну часову мітку (хвилина/сесія) для конкретної одиниці обладнання.

## 2. Бізнес-питання ($\ge 5$)
1. Яка сумарна тривалість робочих циклів та споживання енергії в розрізі класів обладнання згідно з таксономією?
2. Як розподіляються показники температури та вібрації шпинделів за ієрархією таксономії (Клас $\rightarrow$ Підклас)?
3. Які одиниці обладнання мають найбільшу кількість аварійних подій за зміну?
4. Як показники навантаження корелюють із критичними порогами датчиків TS-01?
5. Яка загальна продуктивність обробки деталей у розрізі контролерів PLC-01 та локацій?

## 3. Виміри та таксономія
Система містить 4 виміри:
1. `dim_equipment` — паспортні дані обладнання.
2. `dim_taxonomy` — **таксономічний вимір з IRI** (успадкований з ЛР 5), що описує ієрархію виробничих об'єктів.
3. `dim_time` — часовий вимір (дата, година, зміна).
4. `dim_controller` — параметри контролерів та сенсорів.

## 4. Класифікація мір
* **Адитивні:** `duration_sec` (тривалість), `energy_kwh` (енергоспоживання), `error_count` (кількість помилок).
* **Напівадитивні:** `avg_temperature`, `avg_vibration` (усереднені показники датчиків за сесію).
* **Неадитивні:** `efficiency_ratio` (коефіцієнт корисної дії).

## 5. Політика SCD (Slowly Changing Dimensions)
Для виміру `dim_equipment` застосовується **SCD Type 2** (збереження історії змін технічних характеристик із полями `valid_from`, `valid_to`, `is_current`). Для решти вимірів — **SCD Type 1**.
