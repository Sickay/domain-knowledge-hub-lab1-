Запити до онтології (Competency Questions)

У зв'язку з технічними обмеженнями вбудованого плагіна SPARQL (винятки `NoClassDefFoundError` у середовищі Protégé), перевірка та виконання запитів (Competency Questions) здійснювалися за допомогою логічного раузера **HermiT** та вбудованих механізмів фільтрації екземплярів і класів.

## Компетентнісні запитання (Competency Questions) та їх вирішення:

### 1. Перелік усіх верстатів ЧПК у системі
* **Запит / Критерій:** Фільтрація екземплярів за класом `CNC16K20F3`.
* **Результат виконання:** Раузер успішно ідентифікував індивіди `:CNC_01`, `:CNC_02` та `:CNC_03`.
* **Доказ:** Знімок екрана з вкладки *Individuals / Class hierarchy*, де підтверджено належність екземплярів до відповідного класу.

### 2. Моніторинг стану та температурних режимів обладнання
* **Запит / Критерій:** Перевірка значень властивостей (`Data property assertions`) для виявлення критичних станів (наприклад, перегріву `hasTemp > 75.0`).
* **Результат виконання:** Для індивіда `:CNC_01` зафіксовано нормальний статус (`active`, температура `68.5 °C`), тоді як для аварійних вузлів виявлено перевищення температурних норм.
* **Доказ:** Скріншот панелі Data property assertions для конкретних індивідів.

### 3. Зв'язки між ПЛК-контролерами та керованими об'єктами
* **Запит / Критерій:** Аналіз об'єктних властивостей (`Object property assertions`) зв'язку контролерів із верстатами.
* **Результат виконання:** Підтверджено коректність побудови ієрархії зв'язків керування між екземплярами `:PLC_01` та виробничим обладнанням.
